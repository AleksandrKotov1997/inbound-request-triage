# Разбор входящих заявок

Менеджер вводит заявку и получает тему и черновик ответа. Менеджер проверяет черновик и сам решает, что отправить клиенту. Пользу можно оценить по медианному времени подготовки ответа и доле черновиков, принятых без существенных правок.

## Запуск

Нужен Node.js 20 или новее. Установка зависимостей и ключи AI не требуются.

```sh
node server.mjs
```

Откройте [страницу заявок](http://127.0.0.1:3000). Порт можно задать переменной `PORT`.

## Тесты

```sh
node --test
```

Тесты запускают HTTP-сервер на свободном локальном порту и проверяют страницу, разбор заявок, ошибки ввода, все пять сбоев имитатора и восстановление после таймаута.

## Проверка в браузере

1. Введите «Подскажите условия доставки» и нажмите «Разобрать заявку». Появятся тема «Доставка» и черновик.
2. Введите `[timeout]` и повторите разбор. Старый результат исчезнет сразу. После ожидания появится сообщение о ручном разборе, а введённый текст сохранится.
3. Введите «Подскажите цену» и повторите разбор. Появятся тема «Цена» и новый черновик.

Другие метки имитатора вызывают исключение (`[error]`), битый JSON (`[bad-json]`), неизвестную тему (`[bad-topic]`) и пробельный черновик (`[empty-draft]`).

## Контракт API

`POST /api/triage` принимает JSON с полем `text`. Пустая или пробельная строка, отсутствующее или нестроковое поле и некорректный JSON дают HTTP 400.

| Сценарий | HTTP | Ответ |
| --- | --- | --- |
| Заявка разобрана | `200` | `{"status":"ready","topic":"delivery","draft":"Спасибо за обращение. Уточним детали заявки."}` |
| Ошибка ввода | `400` | `{"status":"invalid_input"}` |
| Модель завершилась ошибкой, вернула некорректный результат или превысила срок ожидания 300 мс | `200` | `{"status":"manual_review","topic":null,"draft":null}` |

Допустимые темы — `delivery`, `pricing` и `other`. Черновик должен содержать видимые символы. При ручном разборе, ошибке сети или некорректном ответе API форма очищает прежний результат и предлагает подготовить ответ вручную.
